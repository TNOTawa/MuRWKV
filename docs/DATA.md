## Notes for the next (GPU) round

1. **Use the resampled 16k corpus (`slakh2100_16k_from_flac`) as the MuRWKV
   training input**: original `all_src.mid` per track (our MT3_FULL_PLUS
   tokenizer incl. ties works unchanged) and 16 kHz mono `mix.wav` — the
   existing `BabySlakh(root, splits=True)` loader indexes it directly
   (train/validation/test = 1288/270/151 indexable; 1289 dirs in train —
   `Track00846` is the documented corrupt exclusion and has no `mix.wav`;
   split lists in `results/splits/slakh2100_flac.json`, exclusion in
   `results/splits/slakh2100_flac_excluded.json`). The FLAC-redux archive is
   kept as the lossless 44.1 kHz source.
2. **Mix tails**: Slakh2100 mixes end with a ~5 s reverb/fade tail after the
   last MIDI note (measured median 5.01 s, p90 7.4 s, max 8.7 s, never
   negative). Gate-1 duration checks accept `-0.5 s <= audio - midi_end
   <= 12 s` (see `src/murwkv/data/slakh_subset.py`); resampled durations
   match the source FLAC to <0.2 s (verified on 60 tracks).
3. **R1 subset artifact** (first generalization round, generated by
   `scripts/prepare_slakh_subset.py`, immutable): `results/splits/
   slakh2100_subset_r1.json` — train 120 + val 20 drawn from corpus-train,
   test 60 drawn from corpus validation+test (pristine held-out; corpus
   held-out songs never enter the training pool). Gate-1-validated (0
   truncation, 16k mono, tail rule); stats in
   `slakh2100_subset_r1_stats.json`. Training entry:
   `python -m murwkv.training.train --exp results/slakh_r1 --data-root
   .../slakh2100_16k_from_flac --splits --tracks $(jq -r '.train[]' ...)`
   (train.py's `--splits` flag respects the corpus split dirs; the default
   track set is corpus-train and never merges held-out songs). Eval:
   `python -m murwkv.eval.eval_heldout --exp ... --data-root ... --splits
   --split test`.
4. **The 307 GB tar is NOT extracted** (extraction would double disk usage to
   ~610 GB). When needed, extract per-track on demand:
   `tar -xf slakh2100_yourmt3_16k.tar -C slakh_preprocessed slakh2100_yourmt3_16k/train/TrackXXXXX`
   or extract the whole train split when the remaining disk allows.
5. The `_16k` (YourMT3+) corpus contains note metadata instead of MIDI —
   usable for a YourMT3-compatible training path, but MuRWKV's tie/EOS
   protocol is designed against the original MIDI (use corpus 1).
6. BabySlakh stays the debug corpus; gate tests reference it.
## Network measurements (2026-08-27, server -> hf-mirror, xet/AWS-backed files)

Direct (no proxy) ceilings: per-connection 0.2-0.6 MB/s (mirror resolver
quotas), aggregate ~2-4 MB/s regardless of concurrency/range size; xet
protocol, direct cas-bridge URLs and alternative mirrors all slower or
unreachable. => IP-level wall to AWS us-east.

**Fix: AutoDL academic accelerator** (`/etc/network_turbo`, internal proxy
http://172.20.0.113:12798): `source /etc/network_turbo` before downloads
→ **~4-5 MB/s per connection and ~48 MB/s aggregate** (measured 2026-08-27).
Use it for all large remote fetches. The 307 GB tar downloads in ~2 h this
way.
